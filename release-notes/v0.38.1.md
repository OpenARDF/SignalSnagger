# SignalSnagger 0.38.1 development release

This pre-1.0 development release promotes the hardware-tested 0.38.1d
candidate. It hardens the recovered 0.38 firmware while preserving its
receiver behavior and experimentally established quadrature strategy.

## User-visible changes

- Tune the Si5351 immediately while editing a memory-bank frequency so the
  received frequency follows each encoder step in both directions.
- Preserve the released headphone-removal 60-second countdown and power-down
  behavior while making its shared state interrupt-safe.
- Apply the supported inclusive 3.500000-4.000000 MHz receiver limits
  consistently and fall back safely to VFO mode when no memory is programmed.
- Report receiver and RTC initialization failures instead of displaying
  successful initialization after a hardware timeout or rejected frequency.

## Stability and reliability

- Prevent torn foreground/interrupt access to multi-byte counters and events.
- Protect Goertzel sample-buffer ownership during three-tone analysis.
- Bound I2C, ADC, EEPROM, and RTC hardware waits so a failed peripheral cannot
  hang the foreground indefinitely.
- Correct EEPROM write widths, operation completion, array bounds, invalid
  enum/channel values, and termination of strings loaded from corrupted data.
- Reject undefined RSSI logarithms and harden signal scoring, diagnostic sample
  indexing, circular buffers, and date/time parsing.
- Remove orphaned, unbuilt LinkBus code and unused legacy LED paths with
  unresolved dependencies.
- Add host regression coverage, deterministic warning-as-error AVR builds,
  repository policy checks, and release documentation.

## Protected receiver behavior

The receiver changes reuse the existing receiver-frequency validation and
`si5351_set_quad_frequency` entry point. The experimentally established Si5351
quadrature implementation, divider and phase relationships, register values,
write order, and reset behavior are unchanged from deployed firmware 0.38.

## Hardware qualification

Hardware evidence is inherited from the immediately preceding 0.38.1d
candidate under the pre-1.0 version-only promotion rule. On 2026-10-19, that
exact candidate was programmed into an AVR128DA48 through Atmel-ICE
J41800053674 using an isolated flash erase. Programmer verification passed; an
independent 128 KiB readback matched the candidate byte-for-byte; EEPROM,
fuses, user row, and lock bytes remained unchanged; and the target reset at
3.31 V. The operator subsequently reported that the requested functional smoke
test passed, including Memories-menu live tuning.

The only changed firmware input between 0.38.1d and this release is the
canonical `SW_REVISION` string. The final 0.38.1 image was not programmed, so
on-device boot/version and functional smoke checks were not performed on that
exact image. These omissions are recorded as a scoped pre-1.0 development
release waiver rather than passing evidence. The final artifact's embedded
version is verified statically during release preparation.
