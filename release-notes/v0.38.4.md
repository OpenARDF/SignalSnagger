# SignalSnagger 0.38.4 development release

This pre-1.0 development release promotes the hardware-tested 0.38.4m
candidate. It improves weak-signal indication, adds selectable 10 Hz tuning and
an uptime display, refines receiver controls and direction indication, and
makes RF-gain audio cues easier to distinguish from received CW.

## User-visible changes

- Add a `Tune Step` setting with persistent 10 Hz and 100 Hz choices. Normal
  tuning uses the selected step; holding the encoder button uses a step ten
  times larger. Existing receivers default safely to the historical 100 Hz
  behavior.
- Use a single detector bin at the selected filter center, with one-update
  exponential smoothing and hysteresis to improve weak-signal LED stability.
  Detector history is reset after gain or frequency changes so stale samples do
  not influence the new tuning point.
- Lower RF-gain feedback to 250 Hz and shorten its Morse-derived timing to
  approximately 25 WPM, keeping it distinct from the normal CW listening tone.
- Add an uptime display showing elapsed minutes and seconds plus the current
  five-minute cycle. Five presses of the same sense button toggle the display;
  other control activity cancels a partial sequence.
- Return automatically from an untouched top-level menu after five seconds,
  while leaving an intentional menu session active after any button or encoder
  activity.
- Limit single encoder-button VFO/memory switching to the normal operational
  display. Returning from VFO keeps the current active memory when it is valid,
  otherwise it selects the next available memory.
- While a sense button selects a cardioid path, show the active path on the
  direction LEDs; releasing the button restores the latest detector color.

## Stability, testing, and release workflow

- Bound the Si5351 fractional PLL calculation for fine tuning with 64-bit
  intermediates while preserving the established quadrature divider, phase,
  register-order, and reset behavior.
- Append the tuning-step setting to EEPROM and treat erased or invalid values
  as 100 Hz without disturbing existing memory data.
- Add host regression coverage for detector smoothing and hysteresis, fine and
  coarse tuning, fractional PLL accuracy, EEPROM fallback, uptime gestures,
  menu-entry timeout, VFO/memory selection, and direction-LED priority.
- Separate firmware and KiCad collector workflows and require SPICE validation
  for KiCad promotion. No pending KiCad or receiver-simulation work is included
  in this firmware release.
- Build with the reference AVR-GCC 7.3.0 and AVR-Dx DFP 1.9.103 profile. Two
  independent builds produced byte-identical ELF and HEX files with zero
  warnings, using 50,841 of 120,000 flash bytes and 3,214 of 12,288 static RAM
  bytes.

## Protected receiver behavior

Displayed and stored frequencies remain operator-facing carrier frequencies.
The selected CW offset remains high-side, and the established Si5351 quadrature
output relationships are unchanged. The new fractional helper changes only how
the requested PLL ratio is represented so 10 Hz carrier steps remain accurate
within the supported receiver range.

## Hardware qualification

Hardware evidence is inherited from the immediately preceding 0.38.4m
candidate under the documented pre-1.0 version-only promotion rule. On
2026-10-25, the operator confirmed that the exact 0.38.4m firmware had been
flashed into and tested on the attached receiver. The receiver ran the
integrated firmware, and no hardware-test failure was reported. Earlier focused
evaluation accepted the single-bin detector near the 800 Hz CW passband center,
with the 100 Hz tuning granularity noted as a limit when comparing nearby tuning
points.

The only changed firmware input between 0.38.4m and this release is the
canonical `SW_REVISION` string. The final 0.38.4 artifact contains the exact
null-terminated unsuffixed version and no suffixed form. The exact 0.38.4 image
was not programmed, so exact-image boot/version confirmation was not performed.

The available release-preparation record does not contain a preserved 0.38.4m
programmer-verification log, independent 128 KiB flash readback, or matching
EEPROM/fuse/lock/user-row comparison, so those checks are not claimed as
passed. A structured repeat of the startup-error and startup-LED checks,
exhaustive tuning/gain/audio/quadrature reception, memory-frequency up/down
checks, all sound combinations, battery calibration, headphone-removal
60-second countdown, power-down, and headphone-reconnect startup was not
performed as part of final release preparation. These omissions are recorded
as not performed, not as passed.
