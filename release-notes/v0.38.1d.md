# SignalSnagger 0.38.1d test firmware

This test candidate supersedes the unflashed 0.38.1c candidate and adds the
Memories-menu live-tuning correction. It is not a published release.

## User-visible change

- Turning the rotary encoder while editing a memory-bank frequency now tunes
  the Si5351 immediately, so the received frequency follows the displayed
  memory frequency in both directions.

## Reliability behavior

- Normalize the legacy `defs.h` copyright text to UTF-8 while preserving all
  0.38 hardware constants and defaults.
- The edited receiver and memory values are committed only after the Si5351
  accepts the requested frequency. A rejected hardware update no longer leaves
  the display or eventual EEPROM value out of sync with the receiver.
- Host regression tests exercise entry from a different VFO frequency, upward
  and downward memory-frequency tuning, hardware rejection, null inputs, and
  the upper band edge.

## Protected receiver behavior

The fix reuses the existing receiver-frequency step validation and
`si5351_set_quad_frequency` entry point. The experimentally established Si5351
quadrature implementation and register sequence remain unchanged.

## Hardware validation

On 2026-10-19, this exact image was programmed into the connected AVR128DA48
through Atmel-ICE J41800053674 using an isolated flash erase. The device
signature was `1E9708`. Programmer verification passed, and an independent
128 KiB flash readback matched the padded candidate byte-for-byte with SHA-256
`10b7c4763d064be91fb29bfec6e51b15e0638e106fb6ffe1f3e438833766548f`.
EEPROM, fuses, user row, and lock bytes were read before and after programming
and remained byte-identical. The target reset into normal execution at 3.31 V.

After the requested functional smoke test, including the Memories-menu
live-tuning correction, the operator reported that the hardware functions
correctly.
