# SignalSnagger 0.38.1c test firmware

This test candidate follows the hardware-validated 0.38.1b image and addresses
the remaining actionable findings from the fresh source review. It is not a
published release.

## User-visible changes

- Accept the documented inclusive receiver limits of 3.500000 MHz and
  4.000000 MHz consistently during tuning and receiver initialization.
- Report receiver initialization failure instead of claiming success when a
  frequency is invalid or the clock generator rejects a frequency change.
- Treat an RTC synchronization timeout as a hardware error and use the existing
  internal-clock fallback path.

## Stability and reliability

- Reuse a host-tested bounded peripheral-status wait and check the RTC
  `PITSTATUS` synchronization register rather than its configuration register.
- Clear stale receiver-initialized state before each new initialization attempt.
- Complete the ISR ownership audit, remove unused volatile globals, and document
  the required atomic-access rules.
- Remove the unused legacy LED code-sending path and its unresolved global
  dependencies; active startup and signal blink behavior is unchanged.
- Remove the orphaned, unbuilt LinkBus source, whose interface was absent and
  whose unsafe legacy implementation could not be compiled or tested.
- Compile the real receiver implementation in host regression tests using
  hardware stubs, covering boundary frequencies and error propagation.

## Protected receiver behavior

The experimentally established Si5351 quadrature implementation and register
sequence remain unchanged from deployed firmware 0.38.
