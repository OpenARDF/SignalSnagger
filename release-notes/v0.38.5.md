# SignalSnagger v0.38.5

SignalSnagger v0.38.5 restores nearly all of the original unfiltered listening
sensitivity while retaining the newer receiver controls, settings, detector,
display, and persistence improvements. It also contains a hardware-watchdog
and audio-backlog circuit breaker so the receiver cannot remain indefinitely
wedged in the UI/audio failure mode encountered during development testing.

## User-visible changes

- Selecting audio filter `OFF` now uses a direct 48 ksample/s ADC-to-DAC path
  with signed, centered, saturating gain. This avoids the sensitivity loss and
  threshold artifacts introduced by routing unfiltered listening through the
  12 ksample/s DSP path.
- The filtered listening and signal-detector paths remain at 12 ksample/s.
- The About screen uses the shorter `V:` label so the complete version fits.
- The About diagnostic row now shows `D<drops> W<reset>L<lockout>`:
  - `D` is the DSP dropped-frame count, capped on screen at 999.
  - `W1` means the current boot followed a watchdog reset.
  - `L1` means the audio-backlog circuit breaker caused that reset.

## Stability and recovery

- A two-second AVR128DA48 hardware watchdog is fed only while foreground code,
  switch/UI scanning, ADC capture, and expected DSP processing all advance.
- Sixty-four consecutive unconsumed DSP frames center the DAC and stop the
  high-priority ADC source. The watchdog then performs a complete receiver
  restart instead of leaving audio active with an unresponsive UI.
- Validated `.noinit` evidence distinguishes an audio-backlog recovery from a
  different watchdog reset without adding EEPROM wear.
- Actual DSP drops replace the earlier timer-wrap diagnostic, which did not
  measure a true missed ADC-result deadline.
- Audio cue/control data uses a double-buffered handoff so the high-priority ADC
  ISR cannot observe a partially updated frame.

## Hardware checks not performed

At the release owner's explicit direction, no additional hardware testing was
performed because the available test time had ended. The following checks are
therefore **not performed**, not passed:

- Programming or readback of the exact unsuffixed `0.38.5` image.
- Deliberately forcing the backlog circuit breaker and observing a `W1L1`
  watchdog recovery.
- Headphone-removal countdown, power-down, and restart.
- Complete tuning-range, RF/audio gain, filtered-audio, quadrature reception,
  direction-switch, LED, battery, and every-menu smoke test.
- Long-duration soak testing intended to reproduce the earlier UI/audio
  lockup.

This is a pre-1.0 development release. The omitted checks leave residual risk
that an untested hardware path or a different lockup mechanism remains.
