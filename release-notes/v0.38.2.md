# SignalSnagger 0.38.2 development release

This pre-1.0 development release promotes the hardware-tested 0.38.1f
candidate. It combines the revised front-end gain scale with quieter,
more focused memory and VFO acceptance behavior.

## User-visible changes

- Accepting a newly selected memory channel or VFO frequency updates only the
  tuning row instead of clearing and redrawing the complete display.
- Side-button acceptance no longer selects a cardioid RF path while frequency
  editing is active, and a long acceptance press remains RF-neutral until the
  button is released.
- Persist only the changed tuning fields when accepting a new setting instead
  of coupling acceptance to a broad EEPROM save.
- Displayed RF gain 0 uses the former RF gain 3 PWM value, displayed RF gain 10
  retains its prior endpoint, and settings 1 through 9 use provisional linear
  interpolation pending measured calibration.

## Stability, testing, and release workflow

- Preserve side-button events for the existing UI while separating the
  platform-neutral switch decision from AVR-specific port control.
- Add host regression coverage for operational cardioid behavior and RF-neutral
  switch handling during frequency editing.
- Enforce immutable-tag publication, the exact two-asset release contract,
  fresh-download verification, and durable post-publication evidence.

## Known follow-up

A brief audio tick or gap can still be heard when the new memory setting is
accepted. The larger interruption and complete display clear are resolved;
the remaining tick is deferred to a separate investigation.

## Protected receiver behavior

The gain change reuses the existing `rf_gain_settings` and `setPWM` path.
Tuning acceptance reuses targeted `EepromManager::updateEEPROMVar` writes and
the display's existing row caches. The experimentally established Si5351
quadrature implementation, divider and phase relationships, register values,
write order, and reset behavior are unchanged.

## Hardware qualification

Hardware evidence is inherited from the immediately preceding 0.38.1f
candidate under the documented pre-1.0 version-only promotion rule. On
2026-10-20, that exact candidate was programmed into an AVR128DA48 through
Atmel-ICE J41800053674 using a flash-only erase. Programmer verification
passed; an independent 128 KiB readback matched the candidate byte-for-byte;
EEPROM, fuses, lock bits, and user row remained unchanged; and the target reset
at 3.31 V. The operator subsequently reported that all requested gain,
display, and tuning-acceptance fixes worked well.

The only changed firmware input between 0.38.1f and this release is the
canonical `SW_REVISION` string. The exact 0.38.2 image was not programmed, as
the release owner explicitly declined additional hardware testing at this
time. Consequently, exact-image boot/version confirmation and the complete
functional smoke test were not performed. The startup/error and LED checks,
exhaustive sensitivity and quadrature checks, headphone-removal 60-second
countdown, power-down, and restart checks were not repeated because those paths
are unaffected by this release. These omissions are recorded as not performed,
not as passed. The final artifact's embedded version is verified statically
during release preparation.
